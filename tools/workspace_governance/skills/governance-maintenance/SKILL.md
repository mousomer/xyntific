Maintain one semantic owner while changing the machinery or declarations that
consume it. This skill orchestrates a migration; canonical policy, applicable
user authorization and required runners still govern the work.

## Bound the migration

1. Resolve the consumer's dispatcher, workspace/project declarations, lock and
   provenance with its declared launcher (`./gov check`, `resolve`, `explain`).
   Inspect the source authority for the fact family being changed. Record the
   current release, consumer bindings, generated consumers and stronger local
   or inherited requirements before choosing a migration boundary.
2. State one semantic objective, acceptance criteria, allowed/forbidden scope,
   compatibility strategy and explicit deferrals. Distinguish general mechanism,
   canonical general policy, skill procedure and project-specific values.
   Repository manifests supply actual paths, commands, owners and profiles.
3. Identify existing acceptance gates and current authorization. A plan does not
   automatically enable a deferred observer, comparator or blocking rule.
   Preserve required owner decisions and independent review for authority or
   policy-family transfers. Prepare a concrete reviewable change before any
   decision that remains necessary; do authorized independent work meanwhile.

## Implement and verify

Prefer an additive path: introduce the mechanism and bindings, route one bounded
flow, verify its consumers, then retire the predecessor after accepted handoff.
Adapters translate declared facts and cannot redefine their semantic owner.
Preserve generated provenance, deterministic identities and applicable replay,
API, sanitation, publication and protected-data contracts.

For each automated obligation, identify its required runner, accepting and
rejecting cases, and actual proof boundary. Test relevant advisory/strict modes,
valid exclusions and suppressions. Keep remaining review duties explicit;
passing structural or proxy checks does not establish semantic preservation.

Use the owning generator for outputs and check deterministic bytes. For shared
skills, maintain one canonical body and verify discovery adapters or generated
copies against it. Verify actual runner integration: installed files alone do
not establish adoption. Reapplication should be idempotent, and checkout audits
must include worktrees, nested boundaries and paths containing spaces.

Use declared runtime/toolchain profiles; avoid fabricated application metadata
for a consumer that only needs governance. Run focused checks, the applicable
full gate, integrity/provenance checks and whitespace/sanitation checks. Follow
the release contract for schema/version/revision changes and explicit lock sync.

Shared kit changes run the kit-owned full verification gate against the explicit
candidate, then the selected immutable components. Keep runtime installation
separate from verification/control components. Source HEAD and publication time
are receipt provenance rather than content identity. Test positive and rejecting
contracts, selected module/catalog origins and unchanged-content reconstruction.

For fleet adoption, use the private explicit registry and guarded saved plans.
Keep default audit structural/evidence-only; request baseline refresh separately
from approved product collection. Preserve execution holds, failed records and
scan gaps. Completed v2 records are collector-reported attestations, not execution
authentication against a same-user actor. Do not retag historical evidence.
Keep private state and undo preimages durable, lock writers during migration,
verify backup restoration and preserve subsequent owner edits. Installer ownership
must not freeze mutable human authorities or backlog text. Activate discovery
links to immutable bodies through guarded preimages and rollback.

## Handoff and evaluation

Update the owning design, affected documentation and open-work tracker before
finalizing. Record unresolved decisions, compatibility retirement conditions,
verification evidence and rollback. Keep machine paths, raw transcripts, private
identities and local keys outside published artifacts.

Assess context cost with observed injected metadata, loaded skill bodies,
resolver output and bounded/full/repeated reads alongside task outcomes. Preserve
exposure gaps and unknown attribution; a smaller file or a passing gate does not
prove savings. Keep project analysis separate from generic capture/reconstruction.
